# Settlement reconciliation, on a domain-blind runtime

A payment gateway sends a payout file. The merchant's ledger says what it thinks
it captured. The two disagree, and reconciling them is the job.

Deterministic rules do the reconciliation. A language model is given only what
the rules provably cannot do — read the gateway's free text and work out which
order it is talking about — and it can only **propose**. A person decides. A
separate, deterministic committer applies, idempotently, against re-verified
evidence, into an append-only log, reversibly.

The runtime underneath knows nothing about payments. It is the same engine
whether it is pointed at a payments platform, a college, or a metro network; the
reconciliation lives in a *pack* on top. Rules 1 and 4 in `goals.md`.

## The numbers

Generated by `python -m packs.recon.eval --write-readme`, measured against
labels the data generator wrote as it built the payout files. Neither the
matcher nor the agent can read those labels — the reader role has no grant on
that table, and the self-checks assert it.

## How it fits together

```
payout CSV ──ingest──► settlement_lines ──┐
                                          ├──► match.py   T0 · T1 · T1b · T2 · T3
kartly.payments (the ledger) ─────────────┘         │
                                                    ├──► matches      (accounted for)
                                                    └──► exceptions   (the queue)
                                                              │
                                        no rule can name it ──┤
                                                              ▼
                                                   agent.py  reads the narration,
                                                             queries read-only,
                                                             proposes  ─┐
                                                                        │
                                            a person approves ──────────┤
                                                                        ▼
                                                              commit.py  applies
                                                              once, verified,
                                                              audited, reversible
```

## Running it

```bash
psql -d kartly -f database/kartly/05_reconciliation.sql \
                -f database/kartly/06_matching.sql \
                -f database/kartly/07_resolutions.sql

cd backend
python -m packs.recon.generate --month 2026-07     # the payout files, and the truth
python -m packs.recon.ingest --reset ../payouts/*.csv
python -m packs.recon.match --reset                 # the rules
python -m packs.recon.agent --all                   # the residual
python -m packs.recon.eval --write-readme           # the numbers above
```

## Self-checks

```bash
cd backend
for t in test_recon_r1 test_recon_r2 test_recon_r3; do .venv/bin/python $t.py; done
```

- `test_recon_r1` — the planted defects are really planted, and the reader role
  cannot see the answer key
- `test_recon_r2` — every match names the payment that truly issued the line,
  each tier caught only its own classes, and no rule ever touched a nameless line
- `test_recon_r3` — eleven attempts to get a change into the ledger without a
  person, all refused
